# v2 1h/4h/1D/1W 共享资金池：周期风险与资金配比研究

**日期**：2026-08-21  
**结论**：**否决当前四周期资金配比采纳**

## 结论摘要

本任务完成了现有 v2 引擎/产物审计、资金配比理论、预注册候选规格、真实数据契约测试、中文报告和 HTML 归档。但没有把未实现的能力伪装成回测结果：当前代码没有让 1h/4h/1D/1W 四个周期同时挂在同一个 Account 上，也没有周期级风险预算、名义占用上限和事件账本。

因此，真实 DEV/OOS 配比验收被执行定义阻塞，没有任何配比可采纳。

## 关键审计

- 710 池铁律通过：实际 710 标的，仅剔除 4 个稳定币变体。
- 重采样通过：1h/4h/1D/1W 使用 OHLCV 聚合；真实数据契约测试通过。
- MACD cache 通过：跨周期必须清空，真实契约测试通过。
- 既有 all-tf runner 每个 `(mode,timeframe)` 调一次 `run_shared`，每次是独立账户，不是四周期共用账户。
- `run_split_tf.py` 只支持一个 long state + 一个 short state，没有 timeframe allocation ledger。
- 当前 unMMR `risk_budget` 只按账户腿数分段，未按周期区分。

这些是独立账户画像，不是组合结果。1h 高频拥挤、1W 样本少且 PF<1，说明配比必须配合硬上限验证，不能按 PF 或平滑度直接分资金。

## 预注册候选

顺序为 `1h/4h/1D/1W`：equal `1/1/1/1`；frequency-decay `1/0.85/0.70/0.55`；user-like-high `1/0.85/0.70/0.70`；user-like-low `1/0.85/0.70/0.50`。

权重只决定每笔风险系数，不等于资金占比。必须同步限制周期风险占用 `R_t` 和名义占用 `O_t`，并记录每次接受/拒绝开仓的周期、风险、手续费、并发和账户状态。
