# V9-2 — 多周期嵌套尧法双均线策略

## 一、策略设计

### 核心思想

5 个时间周期同时对同一品种产生交易信号，各周期独立分配仓位。**同一品种不允许双向持仓**——按净方向决定（Net Direction Reckoning）：

```
净方向 = Σ(多头保证金) - Σ(空头保证金)
- 净方向 > 0 → 只保留多头，强制平掉该品种所有空头
- 净方向 < 0 → 只保留空头，强制平掉该品种所有多头
- 净方向 = 0 → 允许开仓任意方向
```

### 周期参数

| 周期 | 每品种保证金 | 含义 |
|:---:|:-----------:|:----|
| 7d | 0.5% | 大趋势骨架 |
| 1d | 1.0% | 中期方向 |
| 12h | 1.5% | 中短期组合 |
| 4h | 2.0% | 短期交易 |
| 1h | 3.0% | 日内信号 |

- 单个品种最多占用保证金：0.5+1+1.5+2+3 = **8%**
- 全局总保证金上限：**100%** 权益
- 其他共享参数：10x 杠杆, $500 初始, 千一 exit 滑点, 0.04% taker fee

### 入场逻辑（与 V8 一致）

- 尧法 MA20/75（open + 前 N-1 根 close）
- open-based zone 分类
- high/low touch 入场（`high ≥ upper` OR `low ≤ lower`）
- MA20 斜率 >0（多）/ <0（空）
- prev_zone ≠ current_zone（zone transition）

### 冲突处理

当新信号与当前净方向冲突时：
1. 先识别当前品种所有反方向 slot
2. 逐一平仓（标记 `conflict_close`）
3. 重新计算净方向
4. 如果净方向不再冲突 → 开新仓
5. 如果仍然冲突 → 跳过

### 实现架构

`backtest_crypto_dual_ma_v9_2.py` — 独立脚本，不依赖 V8 源码。

优化特点：
- **预计算信号索引**：`signal_index[tf][datetime] → [(product, direction), ...]`，避免逐时间戳扫描全品种
- **searchsorted 指标查询**：`get_bar()` 使用 numpy searchsorted 替代 DataFrame 反复查询
- **统一 1h 时间线**：所有周期信号对齐到 1h 分辨率

## 三、与 V8 基准对比

| 指标 | V8 1h (无过滤) | V8 1h (keep_top_30) | **V9-2 嵌套** |
|:----|:--------------:|:-------------------:|:-------------:|
| Sharpe | 4.64 | 4.83 | **10.25** |
| MaxDD | -74.0% | -51.2% | **-43.3%** |
| 胜率 | 22.3% | 22.4% | **41.1%** |
| 交易数 | 246,997 | 142,417 | 171,657 |

**V9-2 改进效果：**
- Sharpe **+120%**（4.64→10.25）
- 最大回撤 **-27pp**（-74%→-43%）
- 胜率 **+19pp**（22%→41%）

**原因分析：**
1. 多周期叠加 = 不同频率确认同一趋势 → 减少单周期误判
2. 净方向决定剔除反方向仓位 → 减少双向损耗
3. 长周期高胜率（7d 74%）为短周期提供了"趋势锚"

**⚠️ 警告：** 绝对值因 10x 杠杆 × 700 币复利爆炸而失真（ending_equity 10^125）。Sharpe 和 MaxDD% 有相对对比价值，但**不反映实盘可预期收益**。

## 四、方向冲突统计

净方向决定机制在运行中产生的冲突调整（`conflict_close` 与 `conflict_open`）在 `actions.csv` 中记录。典型场景：

```
已有 7d 多头(0.5%)  + 4h 多头(2.0%) → 净方向 +2.5%
  1h 出现空头信号 → conflict！1h 空被拒绝
  1d 出现空头信号 → conflict！先关 7d+4h 多头, 再开 1d 空头
```

净方向逻辑的关键效果：**防止同一品种在不同周期上"自己跟自己反着赌"**。

## 五、已知问题

### 5.1 10x 杠杆复利爆炸（与 V8 同源）

3% 保证金 × 10x 杠杆 × 700 币 × 6 年牛市 → ending equity $10^125。这是**仓位设计问题**，不是代码 bug——实盘需降杠杆或改用 fixed notional。

### 5.2 模拟偏慢（1053s）

因统一 1h 迭代 + 5 周期信号检查在 Python 循环中完成。优化方向：
- 预计算净方向冲突表（离线而非实时）
- 仅在有信号的 timestamps 上做冲突检查

### 5.3 7d 周期信号稀疏（1698 笔）

7d 只有 330 个产品有足够的历史数据。胜率虽高（74%）但 PnL 贡献仅 2%，实际交易价值有限。

### 5.4 回测与实盘差异

- 限价单假设（入场零滑点）在实盘中可能不成立
- 700 币同时交易在实盘中不可能（流动性/保证金不足）
- 实盘需配合成交量过滤（可参考 V8 keep_top_30）
